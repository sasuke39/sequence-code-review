# 业务跳转行选择规则

目标：点击后立刻看到这次需要审查的行为、字段或配置变化，而不是import列表。基于当前源码与diff选择，不使用固定偏移行号，也不要用简单正则“跳过所有注解或声明”。

## 选择顺序

1. 在变更hunk中找首个影响行为、数据结构、接口契约或运行配置的修改行。
2. 若该行是闭括号、空行等缺乏上下文的行，定位所在方法内最近的有效改动语句；必要时定位该方法定义并记录理由。
3. 方法内容被删除时定位当前所属方法或邻近有效上下文，并明确删除；整个文件删除则提供基线diff，不能假装有当前业务行。
4. 新文件跳到核心方法、接口方法、关键字段或配置项，不默认第1行。
5. 同文件多个方法可以有独立Step.line；文件覆盖入口File.line取首个业务改动即可。

## 各语言/文件类型

| 类型 | 通常跳过 | 优先定位 |
|---|---|---|
| Java/Kotlin | package、普通import、版权头、空行、纯格式变化 | 改动方法中的校验/赋值/调用/返回；新增DTO字段及相关注解；SQL/事务/权限等有语义的注解 |
| JS/TS | 普通import/export聚合、纯格式 | 实际函数、事件处理、状态变更；类型契约变化定位对应字段 |
| Vue/React | 仅新增依赖引入 | 条件渲染、事件绑定、业务方法；布局改动定位template/JSX或CSS规则 |
| Mapper XML/SQL | XML声明、纯排版 | 具体statement、查询条件、字段映射或DDL字段 |
| 配置/构建文件 | 无效空白、说明头 | 实际配置键、依赖版本、排除项；这些本身就是有效审查目标 |
| 测试 | import、fixture无关排版 | 相关测试用例和关键断言 |

import并非一概无意义：静态初始化导入、同名类替换、模块副作用导入等可能影响行为。此时标明影响，并优先链接使用位置；若改动只存在于import，保留该行且说明原因。

## 只有非业务改动

若文件仅有普通import整理、换行或格式调整：仍在Git清单和图内文件区列出，用途注明“仅import整理/仅格式调整，无业务逻辑变化”。链接可定位该变更并明确性质，不跳到一个未改动方法冒充业务变更。不要为了隐藏这类文件而删除改动或排除覆盖统计。

## 数据与验证

File输入示例（字段为示意）：

```json
{
  "id": "F001",
  "path": "/workspace/project/OrderService.java",
  "firstChangedLine": 4,
  "line": 86,
  "navigationReason": "第4行仅新增import，第86行是实际新增订单校验",
  "kind": "updated",
  "description": "增加外部订单数量校验"
}
```

交付前读取目标行及前后上下文，确认存在、属于预期方法、对应本次改动，不落在import。文件发生变化后重新定位。当前固定生成器只消费已确定的行号，不声称自动理解Java等语言；准确选择是填数据阶段的责任。
